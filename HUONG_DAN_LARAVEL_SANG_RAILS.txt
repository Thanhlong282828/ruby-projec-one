3. AttendanceServiceProvider PHP CỦA BẠN SANG RUBY RA SAO?
======================================================================
LARAVEL (ví dụ rút gọn theo kiểu bạn gửi):

  class AttendanceServiceProvider extends ModuleServiceProvider
  {
      public function register(): void
      {
          $this->app->bind(
              AttendanceWriteRepositoryInterface::class,
              EloquentAttendanceWriteRepository::class
          );
      }
  }

RAILS (trích register thật, xuống dòng cho dễ đọc):

  def register
    bind "HrmAttendance::Domain::Repositories::ReadRepositoryInterface",
         "HrmAttendance::Infrastructure::Persistence::ActiveRecordReadRepository"
    bind "HrmAttendance::Domain::Repositories::WriteRepositoryInterface",
         "HrmAttendance::Infrastructure::Persistence::ActiveRecordWriteRepository"
  end

Mở: modules/attendance/lib/hrm_attendance/providers/attendance_service_provider.rb

SO SÁNH:
- extends ModuleServiceProvider -> < Hrm::ServiceProvider.
- public function register(): void -> def register ... end.
- $this->app->bind(...) -> bind(...) của lớp cha Hrm::ServiceProvider.
- Eloquent... -> ActiveRecord... vì Rails dùng Active Record.
- Cùng ý nghĩa: khi cần contract này, hãy tạo implementation kia.

Provider chỉ ĐĂNG KÝ cách nối lớp. Provider không thực hiện chấm công.
Container giữ tên lớp bằng chuỗi để phù hợp cơ chế reload của Rails.
Hrm::Container là thư viện tự viết của project, không phải container tích
hợp sẵn của Rails có đầy đủ mọi tính năng như Laravel Container.

Phần schedule/event trong PHP của bạn nằm ở đâu bên Rails?
- Đăng ký repository: provider ở trên.
- Event subscriber: modules/audit/lib/hrm_audit/providers/event_service_provider.rb.
- Scheduler: modules/platform/config/schedule.yml và modules/time_off/config/schedule.yml, Sidekiq Cron; không tự nằm trong provider.
- Route: module có file route riêng, host config/routes.rb gọi draw.
Rails tách các trách nhiệm này ra các file; không dồn hết vào một provider.

4. NAMESPACE, CLASS, BIẾN, CONSTRUCTOR: ĐỌC RUBY NHƯ ĐỌC PHP
======================================================================
PHP                                    Ruby
----------------------------------------------------------------------
namespace HrmAttendance\Application;    module HrmAttendance
                                           module Application ... end
class A extends B                      class A < B
$this->repository                      @repository
new ListAttendances(...)                ListAttendances.new(...)
public function __construct(...)       def initialize(...) ... end
$object->handle(...)                   object.call(...) nếu lớp định nghĩa call
ClassName::CONSTANT                     ClassName::CONSTANT
throw new RuntimeException(...)        raise ...
try / catch                            begin / rescue (hoặc rescue trong method)
null / true / false                    nil / true / false

Ruby module ở đây dùng để nhóm tên, gần với namespace PHP.
Ruby module còn có thể dùng làm mixin; đừng hiểu mọi module Ruby đều là
một module nghiệp vụ kiểu Nwidart.

Ví dụ PHP:
  $query = new ListAttendances($repository);
  $rows = $query->handle(actor: $user, page: 1);

Ruby tương đương về cách gọi:
  query = ListAttendances.new(repository: repository)
  rows = query.call(actor: user, page: 1)

.new tạo đối tượng và chạy initialize.
.call là phương thức bình thường do project đặt tên, gần handle() của bạn.
actor: user là đối số có tên; actor là người đang thực hiện thao tác.
@repository là biến của từng đối tượng, gần $this->repository.
:employee là Symbol Ruby, thường dùng làm tên trường/association/khóa.

Nếu thấy:
  def call(actor:, at: Time.current) = @service.check_in(actor: actor, at: at)

Có thể đọc thành:
  def call(actor:, at: Time.current)
    @service.check_in(actor: actor, at: at)
  end

Đây là cú pháp viết method một biểu thức. Ruby thường trả về biểu thức
cuối cùng nên không nhất thiết có chữ return.
Dấu ! hoặc ? là một phần tên method; ý nghĩa do API quy định.
Ví dụ save! báo lỗi bằng exception khi validation thất bại; active? trả boolean.

8. INTERFACE + IMPLEMENTATION: SO VỚI PHP CỦA BẠN
======================================================================
LARAVEL (ví dụ):
  interface AttendanceReadRepositoryInterface {
      public function list($actor, $page = 1);
  }
  class EloquentAttendanceReadRepository
      implements AttendanceReadRepositoryInterface {
      public function list($actor, $page = 1) { /* truy vấn Eloquent */ }
  }

RAILS (lược namespace, giữ cách triển khai thật):
  class ReadRepositoryInterface
    def list(actor:, page: 1)
      raise NotImplementedError
    end
  end
  class ActiveRecordReadRepository < Domain::Repositories::ReadRepositoryInterface
    # triển khai list và find! bằng Active Record + Pundit scope
  end

Mở hai file:
modules/attendance/lib/hrm_attendance/domain/repositories/read_repository_interface.rb
modules/attendance/lib/hrm_attendance/infrastructure/persistence/active_record_read_repository.rb

SO SÁNH:
- PHP có keyword interface/implements.
- Ruby project này dùng lớp cha làm contract; implementation kế thừa nó.
- Ruby không kiểm tra interface lúc biên dịch như PHP.
- Method chưa triển khai sẽ raise NotImplementedError khi gọi.
- Container kiểm tra implementation thuộc contract; tests kiểm tra các
  method contract được implementation ghi đè.
- Interface định nghĩa cần làm gì; repository thực hiện cách truy cập DB.

Luồng resolve, so với Laravel:
  app(AttendanceReadRepositoryInterface::class)

Bên Ruby:
  Hrm::Container.resolve(
    HrmAttendance::Domain::Repositories::ReadRepositoryInterface
  )

Provider đã bind nên resolve tạo ActiveRecordReadRepository.
Trong constructor Query, dependency mặc định được resolve như vậy.
Có thể truyền repository: fake_repository khi test.
Laravel thường tự inject nhờ container; Ruby này ghi rõ constructor default.

9. ELOQUENT -> ACTIVE RECORD; BLADE -> ERB
======================================================================
LARAVEL (ví dụ):
  Attendance::with('employee')->orderByDesc('work_date')->get();
  $attendance->saveOrFail();
  $attendance->employee;

RAILS:
  Attendance.includes(:employee).order(work_date: :desc).to_a
  attendance.save!
  attendance.employee

Đây chỉ là đối chiếu cú pháp ORM. Repository thật còn áp dụng Pundit scope
và phân trang; không bỏ scope rồi dùng ví dụ trên thay cho code thật.

Model thật: modules/attendance/app/models/attendance.rb
  belongs_to :employee
  validates :work_date, :checked_in_at, presence: true
  validates :work_date, uniqueness: { scope: :employee_id }

SO VỚI LARAVEL:
- belongs_to :employee gần với employee() trả belongsTo(Employee::class).
- validates presence gần rules required; Rails đặt validation tại Model.
- uniqueness scope gần kiểm tra unique kết hợp employee_id + work_date;
  kiểm tra model vẫn cần constraint DB để chống ghi đồng thời.
- ActiveRecord Model kế thừa ApplicationRecord, giống Eloquent kế thừa Model.

Blade:
  @foreach ($attendances as $attendance)
      {{ $attendance->work_date }}
  @endforeach

ERB tương đương:
  <% @attendances.each do |attendance| %>
    <%= attendance.work_date %>
  <% end %>

Mở View: modules/attendance/app/views/attendances/index.html.erb
<% ... %> thực thi Ruby; <%= ... %> xuất kết quả ra HTML.
@attendances được controller chuẩn bị; View không tự viết truy vấn.

role_permissions -> permissions; user_permissions cấp/chặn riêng.
User#allowed?(key) đọc MySQL, không dùng enum role cố định để cấp quyền.

Mở /manage/roles để tạo/chỉnh vai trò (kể cả team_lead/recruiter tùy ý).
Mở /manage/accounts để gán vai trò và quyền riêng cho tài khoản cùng company.
Quyền hiệu lực = quyền vai trò + grant riêng - deny riêng.
Company lấy từ tài khoản đã đăng nhập; không chọn tenant qua params/header.
ApplicationController xác thực; Command/Query/Policy kiểm action + company;
Repository scope theo company; MySQL composite FK chống liên kết chéo.
Các tài khoản cũ thuộc company XINVIEC; không reset/clone dữ liệu.
Đọc từng file và SQL trong HUONG_DAN_COMPANY_PERMISSION_MYSQL.txt.

======================================================================
14. BÀI TẬP ĐỌC THEO KIỂU LARAVEL
======================================================================
Bài 1: Tìm route POST /attendances, xác định action create.
Nó tương ứng store() quen thuộc của Laravel.

Bài 2: Từ create mở CheckIn, rồi mở AttendanceCaptureService.
Tìm hai điều kiện: nhân viên active/probation và chưa chấm công hôm nay.
Nó tương ứng đi Controller -> Handler -> Domain Service ở DJI.

Bài 3: Tìm @repository.save! trong service, rồi mở Write Interface,
provider và ActiveRecordWriteRepository.
Bạn sẽ thấy hợp đồng -> đăng ký bind -> lớp thực thi thật bằng ORM.

Bài 4: Từ index đi ListAttendances -> Read Repository -> View.
Đối chiếu với Controller -> Query Handler -> Eloquent -> Blade.

Khi đã đọc xong Attendance, dùng cùng cách với Workforce, TimeOff, Payroll.
Project hiện có 9 module và 17 repository bindings. Một số module chỉ có
contract cần thiết, không tạo Write Repository giả cho module chỉ đọc.
Đây là nâng cấp kiến trúc Rails hiện có, không phải toàn bộ nghiệp vụ DJI
đa công ty/ca làm/tăng ca/thuế đã được chuyển sang Ruby.

Tài liệu đối chiếu nguồn DJI: docs/DJI_ARCHITECTURE_MAPPING.md.
