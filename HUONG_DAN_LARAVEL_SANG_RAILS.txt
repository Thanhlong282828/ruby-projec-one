0. BẠN HÃY ĐỌC PHẦN NÀO TRƯỚC?
============================================================

Nếu mới chuyển từ Laravel, đọc theo thứ tự:
- Phần 1: bảng đối chiếu Laravel -> Ruby.
- Phần 3: cây thư mục module chấm công.
- Phần 4: lần theo luồng mở trang.
- Phần 5: lần theo luồng bấm Vào ca.
- Phần 6: ServiceProvider và bind/resolve.
- Phần 10: bài tập đọc mã cụ thể.

Không cần hiểu toàn bộ file khởi động ngay. Hãy chọn một thao tác người dùng,
rồi theo đúng đường đi của thao tác đó.

Luồng tổng quát:
Route -> Controller -> Application Command hoặc Query
                        -> Domain Repository Interface
                        -> Infrastructure Active Record Repository
                        -> Model -> MySQL

Domain Service được gọi ở những nghiệp vụ cần quy tắc riêng, ví dụ chấm công
và duyệt phép. View nhận dữ liệu đã chuẩn bị để hiển thị HTML.

Chú ý về Request:
- Các Application Request của Rails hiện làm require/permit: lấy đúng nhóm
  tham số và chỉ chấp nhận các trường trong allowlist.
- Validation dữ liệu vẫn ở Active Record Model.
- Quy tắc nhiều bước của nghiệp vụ ở Domain Service/Application Command.
- Vì vậy Request trong bản này chưa tương đương đầy đủ mọi chức năng của
  Laravel FormRequest như authorize(), rules() và messages().

2. CÁC KHÁI NIỆM QUAN TRỌNG
============================================================

Ruby:
- Ngôn ngữ lập trình, tương ứng vai trò của PHP.

Rails:
- Framework, tương ứng vai trò của Laravel.

Gem:
- Thư viện Ruby, tương tự một package Composer.

Rails Engine:
- Một thư viện có thể mang theo MVC, route, cấu hình và tác vụ cho host Rails.

Application Query:
- Một lớp chuyên xử lý yêu cầu đọc dữ liệu.
- Ví dụ ListAttendances: lấy danh sách chấm công.

Application Command:
- Một lớp chuyên thực hiện thao tác thay đổi dữ liệu hoặc workflow.
- Ví dụ CheckIn: thực hiện vào ca.
- ĐÂY KHÔNG PHẢI lệnh terminal/Artisan. Cùng tên Command nhưng khác ý nghĩa.

Domain:
- Các quy tắc và contract của nghiệp vụ.
- Ví dụ nhân viên inactive không được chấm công; interface quy định những
  thao tác cần thiết mà repository phải cung cấp.

Repository Interface:
- Bản hợp đồng: lớp gọi cần những phương thức gì.
- Trong Ruby dự án này, interface là abstract base class. Gọi phương thức
  chưa triển khai sẽ raise NotImplementedError.
- Ruby không kiểm tra interface ở lúc biên dịch như PHP.

Repository Implementation:
- Lớp thực hiện hợp đồng đó bằng một công nghệ cụ thể.
- Laravel DJI dùng Eloquent; Rails dùng Active Record.

ServiceProvider:
- Nơi chỉ định interface nào được nối với implementation nào.

Dependency Injection (DI):
- Truyền đối tượng cần dùng vào constructor, thay vì gắn chặt code với
  một implementation.
- Mặc định constructor của use case resolve repository từ Hrm::Container.
- Khi test có thể truyền fake repository vào cùng constructor.

CQRS trong dự án này:
- Tách lớp đọc (Query) và ghi (Command) ở mức mã ứng dụng.
- Vẫn dùng chung một database MySQL.
- Chưa có database đọc riêng hoặc Event Sourcing.

6. SERVICEPROVIDER, BIND VÀ RESOLVE
============================================================

Đoạn Laravel bạn quen:

$this->app->bind(
    AttendanceWriteRepositoryInterface::class,
    EloquentAttendanceWriteRepository::class
);

Ý nghĩa: khi một lớp cần AttendanceWriteRepositoryInterface, cung cấp cho
nó EloquentAttendanceWriteRepository.

Trong Rails nâng cấp:
File: modules/attendance/lib/hrm_attendance/providers/attendance_service_provider.rb

bind "HrmAttendance::Domain::Repositories::WriteRepositoryInterface",
     "HrmAttendance::Infrastructure::Persistence::ActiveRecordWriteRepository"

Ý nghĩa tương tự: contract ghi của module chấm công được nối với lớp
triển khai bằng Active Record.

Nơi lấy đối tượng đã nối:

Hrm::Container.resolve(
  HrmAttendance::Domain::Repositories::WriteRepositoryInterface
)

Kết quả là một đối tượng ActiveRecordWriteRepository mới.
Không có binding thì raise MissingBinding, không tự chọn bừa implementation.
Implementation không kế thừa interface thì raise InvalidBinding.

Provider được gọi khi nào?

Gemfile
 -> lib/hrm_attendance.rb
 -> lib/hrm_attendance/engine.rb
 -> Rails to_prepare
 -> AttendanceServiceProvider#register
 -> Container có đủ binding
 -> các use case mới có thể resolve repository

Engine là lớp tích hợp với framework.
ServiceProvider là nơi nối các dependency nghiệp vụ.
Hai trách nhiệm đã được tách rõ.

Tại sao binding dùng chuỗi tên class?
Rails development có thể reload mã. Container giữ tên để tìm class hiện tại,
thay vì giữ mãi class/instance cũ sau một lần sửa file.

7. INTERFACE VÀ IMPLEMENTATION KHÁC NHAU THẾ NÀO?
============================================================

Interface nói: cần làm được việc gì.
Implementation nói: làm việc đó bằng công nghệ nào.

Ví dụ interface đọc có phương thức:

class ReadRepositoryInterface
  def list(actor:, page: 1)
    raise NotImplementedError
  end
end

Lớp ActiveRecordReadRepository kế thừa interface và viết lại list để query.
Query chỉ gọi list qua interface. Nó không phải biết câu SQL cụ thể.

Khi test, có thể viết FakeReadRepository cũng kế thừa interface rồi truyền:

query = HrmAttendance::Application::Queries::ListAttendances.new(
  repository: fake_repository
)

query.call(actor: user, page: 1)

Test của dự án đã kiểm tra cách truyền fake này hoạt động.

Trong bản hiện tại, repository vẫn có thể trả Active Record record và mảng đã load
để dùng thuận tiện với Rails MVC. Chưa tách domain entity thành loại dữ liệu
hoàn toàn độc lập với ORM.

11. CÚ PHÁP RUBY ĐỐI CHIẾU NHANH
============================================================

class A < B
- A kế thừa B, tương tự extends trong PHP.

module HrmAttendance
- Namespace Ruby. HrmAttendance::Application::Commands::CheckIn là tên
  đầy đủ của class, tương tự Modules\\Attendance\\Application\\... trong PHP.

.new
- Tạo một object, giống new trong PHP.

.call(...)
- Gọi phương thức tên call của object.
- Trong các use case của dự án, call là quy ước do mình viết, không phải
  Rails tự động biến class thành business action.

initialize(repository: ...)
- Constructor nhận keyword argument tên repository.
- Nếu caller không truyền, biểu thức mặc định được dùng.

actor: current_user
- Truyền current_user vào tham số tên actor.

@repository
- Instance variable của object, gần với $this->repository.

:employee
- Symbol, thường làm tên/key.

save!
- Lưu thất bại sẽ phát sinh exception; Controller/API adapter xử lý lỗi.

::Employee
- Tìm constant Employee ở namespace gốc.

:: trong tên Ruby
- Dùng để truy cập constant/namespace.
- Không nên hiểu mọi dấu :: đều là PHP static method.

14. PHẠM VI ĐÃ NÂNG CẤP VÀ GIỚI HẠN
============================================================

Đã nâng cấp kiến trúc cho 9 module hiện có:
Platform, Identity, Workforce, Attendance, TimeOff, Payroll, Recruitment,
Audit và Dashboard.

Có 16 repository bindings được nối thực sự vào code chạy:
- Read/Write cho Identity, Workforce, Attendance, TimeOff, Payroll,
  Recruitment và Audit.
- Outbox cho Platform.
- Read tổng hợp cho Dashboard; Dashboard không có Write Repository giả.

Hệ thống vẫn là modular monolith dùng chung MySQL. Giữ model Active Record,
route, database và giao diện vàng đang có. Không đổi thành một hệ thống
microservices hoàn toàn hoặc copy nguyên mọi module của Laravel DJI.

Nghiệp vụ hiện có:
- Nhân sự/phòng ban, ứng viên.
- Một ca chấm công mỗi ngày.
- Nghỉ phép theo ngày lịch trong cùng năm và số dư năm.
- Bảng lương cơ bản, chốt kỳ lương.
- Đăng nhập, API, phân quyền, audit, outbox, queue, realtime, email.

Chưa chuyển các chức năng DJI sau:
- Company/branch tenant isolation, Work Profile, ca xoay, overtime.
- Thiết bị chấm công, anomaly workflow.
- Thuế, bảo hiểm và payroll readiness của DJI.

Đây là những nghiệp vụ cần triển khai riêng với database, policy và test
phù hợp. Không có các job rỗng chỉ để mang tên giống Laravel.

- docs/API.md: HTTP API.
