# Quality gates for Ruby / Rails

GitHub Actions runs on push and pull_request. Two independent jobs check formatting/lint and MySQL tests/autoload/security. Failures return nonzero; CI does not autocorrect or continue-on-error. Branch protection and remote execution have not been configured or certified by this local change.

| Laravel tool/purpose | Ruby project equivalent | Actual scope |
|---|---|---|
| Pint --test | RuboCop with Rails Omakase formatting | Ruby source, engines, tests, migrations, gemspecs and explicit Ruby CLI scripts |
| Larastan framework conventions | rubocop-rails plus Zeitwerk | Rails rules and runtime autoload; not Eloquent-style static type inference |
| PHPStan / Larastan static types | Sorbet + Tapioca gem/DSL RBI | Ten strict Payroll files and real contract calls; gradual typing elsewhere, no claim of numeric PHPStan equivalence |
| Security review / Composer audit | Brakeman all engines + bundler-audit --update | Static vulnerability patterns and current Ruby advisory database |
| PHPUnit/Pest | Minitest | Real isolated hrm_test, business/permission/tenant/CSRF/race tests |
| Architecture tests | bin/check-architecture and bin/check-routes | Thin controllers/views, DI contracts and explicit HTTP route declarations |

Configuration `.rubocop.yml` inherits Rails formatting, explicitly enables all Lint, Security, Rails and Performance groups, and includes extensionless Ruby CLI files. There is no generated todo baseline or engine exclusion. Generated `sorbet/rbi` is excluded from style lint only; Sorbet and Tapioca verify it. Twenty-seven test SQL statements have narrow, documented Rails/SkipsModelValidations exceptions: those regressions intentionally bypass callbacks to test DB constraints or corruption. Production code has no matching exemption. RuboCop does not type-check the entire Rails application and is not a numeric PHPStan level.

Read-only local commands inside the app Ruby environment:

```sh
docker compose exec -T web ruby bin/quality
docker compose exec -T -e RAILS_ENV=test web bundle exec rails test
```

`bin/quality` runs lint, route/architecture guards, Sorbet, secret scan, test-environment RBI verification, Zeitwerk, Brakeman and dependency audit. Tests are separate to keep explicit hrm_test preparation. `bin/test-docker` prepares the isolated SQL schema/guards before tests. Do not run setup/seed against existing business data just to check code.

Intentional formatting fixes were applied in groups with user authorization and reviewed against a private source snapshot. Functional corrections include strong parameter root-shape validation using Rails expect, explicit base initialization, inverse associations, reuse of immutable lookups, localization preserving messages and Pathname-to-string conversion in the container contract test. All authorization, transaction, audit and DB constraints remain mandatory.

Workflow validation: actionlint 1.7.7. Test and scanner evidence is recorded in VERIFICATION.md. No GitHub push, remote check success or protected-branch requirement is implied by local success.

References: [PHPStan rule levels](https://phpstan.org/user-guide/rule-levels), [Rails Omakase](https://github.com/rails/rubocop-rails-omakase), [RuboCop Performance](https://docs.rubocop.org/rubocop-performance/latest/usage.html).

## Static types and reproducible verification — 2026-11-13

Ruby 3.4.12 / Rails 8.1.4.1 / MySQL 8.4 were checked with locked Sorbet 0.6.13672 and Tapioca 0.20.0. `sorbet-runtime` is a production dependency of Payroll; compiler/generator are development/test tooling.

Ten `typed: strict` authored files: `FinalizePayRun`, `ListPayslips`, `ReconcilePayRun`, Payroll read/write repository contracts, both ActiveRecord read/write implementations, `PayrollReconciliation` and `Domain::ReconciliationResult` and `Domain::Snapshot` (string-key shape, separate file for cold autoload). Calls are typed through the injected contract, not by declaring an unchecked concrete repository in an RBI. Source outside this slice remains gradual/untyped. Nil actors still raise Pundit authorization errors; nil page, absent historic snapshot and unavailable projections retain existing behavior. Period accepts HTTP String/Date/nil, leaving invalid input to existing Rails validation.

Dynamic boundaries are explicit casts at string-based Container resolution, Pundit/materialized pagination results and ActiveRecord JSON deserialization. No authored `T.unsafe` or `T.untyped` was added to this slice. Generated library RBI contains untyped APIs; strict is not a proof of every framework API or deep validation of privileged SQL-corrupted JSON. Newly captured snapshots are generated by the checked method. Tapioca automatically marks 12 conflicting Ruby standard-library/tooling gem RBI as typed:false (the generation log records them); do not manually edit generated files or suppress application type errors.

```sh
# Inside a prepared Ruby app container (test database only for generation):
RAILS_ENV=test bundle exec tapioca gem --workers=2
RAILS_ENV=test bundle exec tapioca dsl --workers=1
ruby bin/typecheck --self-test
RAILS_ENV=test ruby bin/check-rbi
ruby bin/check-secrets --self-test
# Host with Docker, from this repository:
RAILS_ENV=test ruby bin/verify-test-schema
ruby bin/smoke-image
```

The negative type probe creates a temporary strict file, proves error 7002 for a String passed to the real WriteRepositoryInterface.finalize! PayRun parameter, and removes the file on exit. `bin/check-rbi` fails unless Rails uses hrm_test, all 12 Engines load and bindings resolve. Gem verify checks dependency RBI inventory/versions; DSL verify regenerates in memory to detect schema/source drift. No auto-generated todo stubs remain; Sidekiq API and Minitest Mock are required explicitly for generation, and the extensionless ENV-audit CLI is included as real source. A minimal shim names Bundler’s vendored ConnectionPool/ForkTracker used during gem generation; no application methods are invented. `check-shims` rejects duplicate shim declarations. Full byte-for-byte gem RBI regeneration is not implied by inventory verification.

`config/engine_boundaries.yml` records current API dependencies and the narrowly allowed legacy transport error rescue. Controllers cannot resolve repositories or instantiate infrastructure. Providers bind their own contracts to their own implementation namespaces; every repository contract needs one binding. Cross-engine Infrastructure/Provider references and undeclared API edges fail. Source comments (including Laravel learning examples) are ignored. These are structural guards for a shared-schema modular monolith, not a claim of isolated databases or exhaustive model-dependency enforcement.

Gitleaks 8.30.1 is pinned by image digest in Dockerfile. The scan covers publishable working-tree files, including untracked source, with fully redacted output and metadata-only findings. It does not scan local ignored .env/private keys/backups or rewrite Git history. Private env/key paths that become publishable (including force-added .env) fail on filename alone before contents are read; a regression uses an unreadable dummy .env to verify this. The sole allowlist combines exact generated URI RBI path with its exact public documentation example; no engine/gem directory is skipped. The negative synthetic-token probe also verifies redaction. `.env.example` uses CHANGE_ME; setup replaces that exact Rails-key placeholder with a fresh 128-hex key before writing mode0600 and preserves existing .env files (`--env-only` is testable without Docker).

Query budgets are measured without query cache, excluding schema and transaction-control SQL: at 1 and 20 employees, employee list incl. department uses 9, reconciliation20, CSV creation49 queries. Regression permits at most +1 with row growth and fixed ceilings11/22/52. This measures database round trips, not production latency/load.

`bin/verify-test-schema` creates/drops only a randomly named disposable hrm_test_schema_* database, loads structure.sql and compares columns, FK/index/CHECK definitions, trigger bodies and migration versions, as well as counts to hrm_test. `bin/smoke-image` checks non-root, SQL schema, no legacy schema/private env/key files, and HTTP 200/200/302, mounting only the public MySQL CA.

On 2026-11-13, Git schema 9b9c014 (version 20261028000002) was independently upgraded from 3 to 17 migrations in a disposable network-disabled MySQL 8.4 container using invented two-company fixtures. Definitions match fresh structure.sql and legacy read/snapshot/CSV/constraint checks pass. No new migration required.
